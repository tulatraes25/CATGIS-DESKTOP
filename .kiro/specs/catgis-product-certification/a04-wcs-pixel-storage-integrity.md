## Confirmed source evidence

`WcsClient.validateStagedTiff()` on baseline checks TIFF/BigTIFF signature,
ImageIO reader format and 2-D dimensions. The later GeoTools validation checks
embedded CRS/BBOX but only reads georeference metadata. A valid TIFF header
with a StripOffsets/TileOffsets value past EOF can pass these preliminary
checks, yet the user receives unreadable or incomplete raster pixel data.

## Requirements

1. Keep stream-to-sibling-stage, error-response filtering, HTTP length
   checks and WCS 2.0.1 -> WCS 1.0.0 fallback. Validate before the existing
   rename. Always retain original destination on rejection and delete
   `.catgis-wcs-*.part` after caught failures.
2. Inspect the **primary** TIFF IFD using Java 17 `TIFFDirectory` metadata.
   Require exactly one of strip or tile storage modes, matching offset/count
   lengths with 1 to 2,000,000 entries. Reject zero/sparse/unbounded/
   out-of-file blocks, including arithmetic overflow and invalid metadata.
   No full-image read while inspecting the IFD.
3. Use `ImageReadParam.setSourceRegion` for 1x1 decoded pixels at
   top-left, center and bottom-right. Reject failed decodes, unexpected
   dimensions or invalid band counts. Allow legitimate floating-point
   NaN NoData values; a sampled NaN is *not* automatically corruption.
4. Verify real on-demand GeoTIFF fixture generated by GeoTools/GeoTiffWriter
   at multiple grid sizes (including 1024x1024), plus WCS 1.0.0 fallback.
   One negative fixture changes only a primary TIFF strip/tile **offset**
   beyond EOF while preserving parseable TIFF dimensions and GeoKeys. Both
   WCS versions must reject it without changing a previous file; if WCS 2.0
   is corrupted but V1 is complete, publish only the V1 bytes.
5. Keep file handles closed on Windows and respect Swing EDT isolation
   from existing WCS caller contracts. Maintain explicit PNG/non-TIFF
   compatibility; this change is only for requested TIFF aliases.

## Explicit limitations / stop conditions

- Sampling three 1x1 regions is **not** an exhaustive checksum of all
  pixels, overviews or NoData/bands. No scientific full-integrity PASS.
- A compressed TIFF decoder may internally decompress more than the
  requested source region; 1x1 output does not imply a hard heap bound.
  Decoder resource-budget/load tests are another issue #43 gate.
- Untrusted huge streaming responses remain separately budgeted (memory
  is bounded by disk streaming, not overall disk footprint). Network/disk
  full, cancellation, and unsupported TIFF storage must fail safely.
- The metadata-only JDK reader may reject unusual valid TIFF variants,
  including sparse strips, until covered with real authoritative fixtures.
  Fail-closed rather than silently publishing scientifically dubious data.
- Java 17 PR CI/Certification across Windows/Linux/macOS Intel/ARM and
  exact-prior-main attestation must PASS. Then normal expected-head merge,
  exact merged main event=push CI+Certification, authenticated attestation.
  Real native Windows OSGeo4W/JNI/GUI remain separate requirements.
- Keep #43 and A0.7 OPEN until full scientific/raster acceptance.

No personal/user workstation data, native binary fixtures or secrets added.
